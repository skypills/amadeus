# Безопасность и приватность

## Границы доверия

- Модель **не** получает произвольный shell.
- Любое системное действие проходит через `ToolRegistry` и `PermissionPolicy`.
- Инструмент вне реестра отклоняется; приложения — только из allowlist.
- Модель автоматически вызывает только низкорисковые инструменты. Запуск
  приложений не предлагается модели и требует подтверждения пользователя.
- Действия с высоким риском запрещены политикой; средний риск и опасные
  операции требуют явного подтверждения пользователя.
- Содержимое веб-страниц и документов считается недоверенным вводом.
- Веб-поиск по умолчанию не вызывается моделью сам; включается явно.
- Результаты поиска передаются с отдельной границей «недоверенные данные»,
  а не как системная инструкция; модель не должна выполнять команды со страниц.
- Ссылки берутся из выдачи поисковика, а не генерируются моделью.
- Модель не сохраняет факты сама: предложение попадает в очередь и требует
  явного подтверждения пользователя (в CLI и GUI).
- Ассистент запускается от обычного пользователя; root и неограниченный sudo
  не используются.

## Приватность

- Локальная модель — режим по умолчанию.
- Облако включается только явно (`allow_cloud = true` + подтверждение в CLI).
- Перед облачным запросом пользователь получает уведомление.
- История и факты не отправляются в облако, пока не включены
  `privacy.send_history_to_cloud` и `privacy.send_facts_to_cloud`.
- При отключённом интернете локальный текстовый диалог продолжает работать.
- В облачном режиме результаты инструментов могут уйти провайдеру вместе с
  запросом; режим включается только явно.
- GUI не перехватывает глобальные клавиши: горячий вызов настраивается в
  Hyprland через `bind`.
- Генерация выполняется в фоновом потоке; остановка не сохраняет частичный
  ответ как завершённый.
- Скриншоты требуют подтверждения, сохраняются локально в каталоге данных и
  не отправляются в сеть. Открытие URL допускает только http/https и требует
  подтверждения. Текст буфера обмена не пишется в логи.
- Голосовые записи обрабатываются локально и удаляются после распознавания.
  STT/TTS не отправляют аудио в облако; озвучка хранится только локально.
- Запись можно отменить, а озвучивание — остановить в любой момент.

## Секреты

- API-ключи читаются из переменных окружения (`AMADEUS_CLOUD_API_KEY`).
- `.env` и базы данных исключены из Git через `.gitignore`.
- Ключи не выводятся в логи и сообщения об ошибках.
- В репозитории хранится только `.env.example` без значений.

## Пользовательские данные

```
~/.config/amadeus/settings.toml
~/.config/amadeus/persona.md
~/.local/share/amadeus/amadeus.db
~/.local/state/amadeus/
```

Просмотр и удаление:

- `/history` — текущая сессия;
- `/sessions`, `/search` — вся история;
- `/delete <id|all>` — удаление сессии или всех данных;
- `/facts`, `/fact pending`, `/fact accept|reject <id>`,
  `/fact edit <id> <текст>`, `/fact del <id>`, `/fact clear` — управление
  фактами и предложениями;
- `/summarize`, `/summary clear` — локальная сводка сессии; в облако она уходит
  только при `privacy.send_history_to_cloud`;
- `/export [путь]` — экспорт истории, фактов и предложений в JSON; настройки и
  секреты в экспорт не попадают.

## Логи

- Лог: `~/.local/state/amadeus/amadeus.log`, ротация до 1 МБ × 3.
- Пишутся запуск, версия и ошибки; API-ключи и тексты диалогов не пишутся.
- `amadeus --diagnose` не выводит ключи и содержимое переписки.

## Ошибки

Недоступность Ollama, модели, облака или сети превращается в понятное
сообщение и не завершает приложение аварийно. Пустой ответ модели не
сохраняется как ответ ассистента.
