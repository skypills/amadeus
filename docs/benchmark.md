# Диагностика и измерения

## `amadeus --diagnose`

Показывает:

- версию Amadeus и Python;
- ОС, ядро, CPU, потоки, RAM, uptime, load average, диск и GPU;
- пути конфигурации, данных и логов;
- статус провайдера и список моделей Ollama;
- состояние записи, STT, TTS и плеера;
- число сессий, фактов и ожидающих предложений.

Команда не выводит API-ключи и содержимое диалогов. Её удобно приложить к
отчёту об ошибке.

## `amadeus --benchmark`

Запускает короткий запрос к локальной Ollama и печатает:

- время до первого токена;
- общее время;
- число сгенерированных токенов и токенов промпта;
- скорость в токенах в секунду;
- доступную RAM;
- JSON можно сохранить: `--benchmark-out report.json`.

Первый запуск может быть медленнее: модель загружается в память. Сделайте
2–3 замера и сравнивайте установившиеся значения.

Пример формы отчёта (числа будут вашими):

```
Amadeus benchmark
Модель: <model>
Первый токен: <ms> мс
Всего: <ms> мс
Токенов сгенерировано: <n>
Токенов промпта: <n>
Скорость: <tokens/s> ток/с
RAM всего/доступно: <total> / <available>
```

## Как выбирать модель

- Если доступной RAM мало или скорость ниже комфортной — начните с 3B–4B.
- 7B–8B проверяйте только после замера: сравните скорость, качество русского
  языка и объём свободной памяти.
- Следите за `ollama ps`: модель может занимать GPU/CPU и RAM.
- Не запускайте одновременно несколько моделей и тяжёлые приложения.

## Ограничения

- Benchmark использует только Ollama; облачный провайдер не задействуется.
- Сетевые задержки не входят в скорость генерации: считаются токены и
  `eval_duration` от Ollama.
- На результат влияют квантование, backend (CPU/CUDA/ROCm), драйверы и
  фоновые процессы.
