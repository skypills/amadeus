# Архитектура Amadeus

## Принцип

Одно ядро — несколько интерфейсов. CLI (этап 1), GUI и голосовой pipeline
вызывают `Assistant` и не дублируют бизнес-логику.

## Слои

| Слой | Модули | Ответственность |
|---|---|---|
| CLI | `cli.py` | ввод/вывод, команды, подтверждения |
| GUI | `ui/window.py`, `ui/chat.py`, `ui/settings.py` | PySide6-окно, чат, история, настройки, статус |
| Core | `core/assistant.py`, `context.py`, `router.py`, `events.py` | сборка запроса, диалог, выбор провайдера, события |
| Providers | `providers/ollama.py`, `cloud.py`, `base.py` | единый интерфейс генерации и потокового вывода |
| Memory | `memory/database.py`, `history.py`, `facts.py`, `proposals.py`, `retrieval.py`, `export.py` | SQLite, FTS5, история, факты, подтверждение, экспорт |
| Personality | `personality/prompts.py`, `mood.py` | persona.md, системный промпт, стиль |
| Voice | `voice/recorder.py`, `stt.py`, `tts.py`, `player.py`, `pipeline.py` | запись, whisper.cpp, Piper, воспроизведение |
| Security | `security/permissions.py` | allowlist, уровни риска, подтверждения |
| Tools | `tools/registry.py`, `notifications.py`, `applications.py`, `system_info.py`, `web_search.py` | реестр и разрешённые действия |
| Storage | `storage/paths.py`, `logging_setup.py` | platformdirs, логи с ротацией |
| Diagnostics | `diagnostics.py` | железо, статус, benchmark |

## Поток запроса

1. CLI получает текст.
2. `Assistant.respond` сохраняет сообщение пользователя в SQLite.
3. `Router` выбирает провайдера по настройкам и правилам приватности.
4. `Retrieval` ищет факты и фрагменты прошлых сессий (FTS5).
5. `build_system_prompt` соединяет persona, настроение и память.
6. Провайдер генерирует ответ и отдаёт чанки в CLI.
7. Успешный ответ сохраняется в историю.
8. Если пользователь явно просит запомнить факт, создаётся запись в
   `fact_proposals`; CLI спрашивает подтверждение и только затем переносит
   факт в `facts`.
9. При ошибке локальной модели и разрешённом облаке выполняется один
   повторный запрос через облако с уведомлением пользователя.

## Этап 8: умная память

- **Сводки сессий.** `session_summaries` хранит сжатую сводку и номер последнего
  сообщения. `/summarize` строит её через выбранного провайдера; при облаке
  требуется `privacy.send_history_to_cloud`.
- **Длинный контекст.** Если история усекается `history_limit`, сохранённая
  сводка добавляется к системному контексту, чтобы не терять старые решения.
- **Факты.** Редактирование через `/fact edit` и GUI; дубликаты отклоняются,
  FTS-индекс обновляется триггером.
- **Экспорт.** Сводки входят в JSON-экспорт вместе с историей и фактами.
- **GUI.** Кнопка «Сводка» в истории, кнопка «Изменить» в фактах; сводка
  создаётся в отдельном потоке с собственным подключением к SQLite.

## Этап 7: стабилизация

- **Диагностика.** `amadeus --diagnose` собирает железо, пути, статус провайдера,
  голос и счётчики данных без секретов.
- **Benchmark.** `amadeus --benchmark` измеряет первый токен, общее время,
  токены и токены/сек; отчёт можно сохранить в JSON.
- **Логи.** Ротация в `~/.local/state/amadeus/amadeus.log`; пишутся только
  события запуска и ошибки, без ключей и содержимого диалогов.
- **Тесты ошибок.** Провайдеры, сеть, голос, поиск и инструменты покрыты
  тестами отказов; ошибки превращаются в сообщения, а не падения.
- **Установка и автозапуск.** Пошаговая инструкция в `docs/installation.md`,
  `.desktop` и autostart-файл в `packaging/`, горячий вызов через Hyprland.
- **Измерения.** Выбор модели документирован в `docs/benchmark.md`; числа
  зависят от конкретного CPU/GPU и квантования.

## Этап 6: веб-поиск

- **Отдельный адаптер.** `WebSearch` использует `ddgs` (DuckDuckGo) и резервный
  HTML-парсер. Возвращает title, URL, выдержку и дату, если она есть.
- **Реальные URL.** Ссылки извлекаются из выдачи, редиректы DuckDuckGo
  разворачиваются; дубликаты отбрасываются. Модель получает только эти URL.
- **Недоверенный ввод.** Источники передаются отдельным сообщением с явной
  границей «недоверенные данные», а не как системная инструкция. Модель должна
  отличать их от своих знаний и не выполнять инструкции со страниц.
- **Явный запуск.** Веб-поиск запускается `/web` или пунктом GUI; по умолчанию
  `allow_model_calls = false`, поэтому модель не ходит в интернет сама.
- **Ошибки.** Недоступность поисковика не ломает локальный диалог: выводится
  понятное сообщение.
- **Облако.** Облачный провайдер остаётся явным; при передаче показывается
  уведомление, а история/факты отправляются только по отдельным флагам.

## Этап 5: инструменты

- **Реестр.** Каждый инструмент описан именем, риском, JSON-схемой аргументов и
  обработчиком. Незарегистрированный инструмент выполнить нельзя.
- **Модель.** Низкорисковые инструменты передаются провайдеру как function
  calling (Ollama и OpenAI-совместимый API). Модель может запросить
  `system_info` и `send_notification`; результат возвращается в диалог.
- **Подтверждения.** `launch_application` имеет средний риск, не предлагается
  модели и требует явного подтверждения в CLI/GUI. Высокорисковые действия
  политикой запрещены.
- **Allowlist.** Список приложений и необходимость подтверждения задаются в
  `[security]`; аргументы передаются списком без shell.
- **Деградация.** Если модель не поддерживает tools, ядро автоматически
  продолжает обычный диалог; при ошибке инструмента модель получает текст
  ошибки, а приложение не падает.

## Этап 4: голос

- **Внешние локальные инструменты.** Запись — `parecord`/`pw-record`/`arecord`,
  STT — `whisper-cli` (whisper.cpp), TTS — `piper`, воспроизведение —
  `pw-play`/`paplay`/`aplay`/`ffplay`. Пути и команды настраиваются.
- **Никакого облака.** Аудио и распознанный текст не уходят в сеть.
- **Приватность.** Запись удаляется сразу после распознавания. Последний
  синтезированный файл перезаписывается.
- **Потоки.** Запись стартует/останавливается из GUI без блокировки; STT и
  TTS выполняются в `VoiceWorker`, чтобы окно оставалось отзывчивым.
- **Управление.** Кнопки записи/отмены, озвучивания и остановки TTS; в CLI
  команды `/listen`, `/say`, `/voice`.
- **Деградация.** Если бинарник или модель не найдены, приложение работает
  дальше, а статус честно показывает, что голос не настроен.

## Этап 3: GUI

- **Общее ядро.** GUI вызывает `Assistant`, историю, факты и настройки, а не
  дублирует бизнес-логику.
- **Потоки.** Генерация и проверка статуса выполняются в `QThread`, поэтому
  интерфейс не блокируется. `ChatWorker` создаёт собственное подключение к
  SQLite в своём потоке; главное окно использует своё.
- **Остановка.** Кнопка «Остановить» выставляет флаг; следующий чанк вызывает
  `GenerationCancelled`, поток корректно завершается, ответ не сохраняется
  как завершённый.
- **История и память.** Слева — сессии с поиском и вкладка фактов/предложений.
  Подтверждение факта доступно и после перезапуска.
- **Настройки.** Диалог меняет `settings.toml`: Ollama, провайдер, облако,
  настроение и параметры стиля; персона редактируется отдельно.
- **Hyprland.** Глобальная клавиша настраивается в WM (`bind = SUPER, A,
  exec, amadeus-gui`), приложение не перехватывает ввод глобально.

## Этап 2: память и личность

- **Подтверждение фактов.** Предложения хранятся отдельно от подтверждённых
  фактов. Причина — не давать модели превращать догадки в «истину».
- **Явный триггер.** Факт предлагается по `/remember` или по фразе «запомни…»,
  без фонового анализа всей переписки. Это предсказуемо и не тратит лишние
  токены.
- **Очередь подтверждений.** «Позже» сохраняет предложение в БД, его можно
  принять через `/fact accept` после перезапуска.
- **Экспорт.** `/export` выгружает историю, факты и предложения в JSON, не
  включая настройки и секреты.
- **Характер.** `mood`, `familiarity`, `verbosity`, `initiative` сохраняются в
  `settings.toml`; `persona.md` остаётся редактируемым источником роли.
- **Контекст переживает перезапуск.** CLI продолжает последнюю сессию, факты
  и предложения лежат в SQLite.

## Решения этапа 1

- **Ollama через stdlib `urllib`** — меньше зависимостей, проще установка;
  при необходимости провайдер можно заменить, не меняя ядро.
- **SQLite + FTS5** — история и поиск без сервера. Если FTS5 недоступен,
  поиск автоматически деградирует до `LIKE`.
- **Факты только по явной команде** — модель не сохраняет догадки как факты.
- **Облако выключено по умолчанию** — отдельные флаги для истории и фактов.
- **Память текущей сессии** хранится в истории; долговременные факты — отдельно.
- **События** (`EventBus`) отделяют уведомления от интерфейса: CLI печатает их
  в stderr, GUI показывает в статусной строке.
